# GS 自动数据采集爬虫（多用户版）

在管理员机器上集中运行，每天 **09:00** 和 **18:00** 为所有 GS 组员自动采集数据、生成 AI 日报，结果直接写入各自的 App 账号，无需任何人工干预。

---

## 第一次使用（按顺序做完这 6 步）

### 第一步：安装运行环境

打开命令行，进入 `crawler` 文件夹，依次执行：

```
npm install
npx playwright install chromium
```

**成功标志**：看到 "Chromium 下载完成" 字样，没有红色报错。

---

### 第二步：填写后台账号信息

找到 `.env.crawler.example` 文件，**复制一份**并改名为 `.env.crawler`（注意去掉 `.example`），然后用记事本打开，把里面的示例值替换成真实的：

| 变量名 | 填什么 |
|--------|--------|
| `GM_CHAT_URL` | 聊天后台的网址，如 `https://chat.example.com` |
| `GM_CHAT_USERNAME` | 聊天后台的登录账号 |
| `GM_CHAT_PASSWORD` | 聊天后台的登录密码 |
| `GM_RECHARGE_URL` | 充值后台的网址 |
| `APP_SERVER_URL` | **不用改**，保持 `http://localhost:3000` |

> `.env.crawler` 包含账号密码，不会被上传到 git，请妥善保管。

---

### 第三步：填写各 GS 组员的信息

打开 `users.json`，按下面的格式，给每位 GS 添加一条记录：

```json
[
  {
    "gsUserId": "GS的App账号ID",
    "gsGroup": "杭州三组",
    "serverName": "傲世1区",
    "rechargePlayerIds": ["10011234", "10056789"]
  }
]
```

**各字段说明：**

- **`gsUserId`**（GS 在 App 里的账号 ID）  
  找法：让 GS 登录 App，进入**个人中心**，可以直接看到并一键复制"账号 ID"。

- **`gsGroup`**：该 GS 所在的分组名称，如"杭州三组"

- **`serverName`**：该 GS 负责的区服名称，**必须和 App 里配置的区服名完全一致**，如"傲世1区"

- **`rechargePlayerIds`**：需要监控的玩家游戏 ID 列表（数字格式），由 GS 提供其重点关注的玩家 ID

---

### 第四步：登录聊天后台（只需做一次，过期了再重做）

在命令行执行：

```
npm run auth:chat
```

→ 程序会**自动弹出一个浏览器窗口**，账号和密码已经自动填好  
→ 你只需要**手动输入验证码**，然后点登录  
→ 登录跳转成功后，浏览器会自动关闭  
→ 命令行显示 `✓ 聊天后台 session 已保存` 即代表成功  

登录状态通常保持数天，过期后重新执行此命令即可。

---

### 第五步：登录充值后台（只需做一次，过期了再重做）

在命令行执行：

```
npm run auth:recharge
```

→ 程序会**自动弹出一个浏览器窗口**，显示二维码  
→ **用手机扫码**完成登录  
→ 登录成功后浏览器自动关闭  
→ 命令行显示 `✓ 充值后台 session 已保存` 即代表成功

---

### 第六步：告诉程序在哪里点按钮（一次性配置，需要查 GM 后台）

爬虫需要知道 GM 后台页面上各个输入框和按钮的位置，才能自动操作。你需要打开 `gmClient.ts` 文件，把所有 `// replace selector` 注释旁边引号里的内容，替换成 GM 后台真实的位置标识。

**怎么找按钮/输入框的位置标识：**

1. 用 **Chrome 浏览器**打开 GM 后台，登录进去
2. 按 **F12** 打开开发者工具
3. 点工具栏**左上角的箭头图标**（"选取元素"按钮）
4. 在页面上**点击你要定位的按钮或输入框**
5. 右侧 HTML 区域会高亮显示该元素
6. **右键点高亮的 HTML 行 → 复制 → 复制 selector**
7. 把复制到的内容粘贴到 `gmClient.ts` 对应位置（替换引号里的旧内容）

**需要定位的地方共 8 处（分两个页面）：**

聊天导出页：
- 时间"开始"输入框
- 时间"结束"输入框
- "查询"按钮
- "导出"按钮（点了会下载文件的那个）

充值查询页：
- 玩家 ID 输入框
- 时间"开始"输入框
- 时间"结束"输入框
- "查询"按钮
- "下一页"按钮（如果没有分页可以忽略）

**另外**，打开 `parser.ts` 文件，找到顶部的 `RECHARGE_COL_MAP`。打开充值查询页，数一数表格从左到右各列分别是什么内容（第 1 列 = 数字 0，第 2 列 = 数字 1，以此类推），然后把金额、角色名、状态、支付方式对应的列号填进去。

---

### 完成！测试运行

确保 App 的后端服务已经在运行（先执行根目录的 `npm run dev`），然后在命令行执行：

```
npm run now
```

如果每个区服都打印出 `✓ Daily report generated`，说明一切正常。

之后让程序保持在后台持续运行：

```bash
# 简单方式：直接运行，关掉命令行就停
npm start

# 推荐方式：用 pm2 在后台守护运行
npm install -g pm2
pm2 start dist/index.js --name gs-crawler
pm2 save        # 保存配置
pm2 startup     # 设置开机自启
```

---

## 登录过期怎么办？

当命令行出现 `⚠ Session expired for chat/recharge backend` 时，说明某个后台的登录状态过期了，重新执行对应的认证命令即可：

```
npm run auth:chat      # 聊天后台过期
npm run auth:recharge  # 充值后台过期
```

重新登录后，下次定时任务会自动使用新的登录状态，不需要重启程序。

## 文件说明

| 文件 | 作用 |
|------|------|
| `users.json` | 所有 GS 组员配置（管理员维护） |
| `.env.crawler` | GM 后台账号密码（不提交 git） |
| `sessions/` | 登录状态文件（不提交 git，自动生成） |
| `auth.ts` | 认证脚本（第四、五步调用的） |
| `gmClient.ts` | 自动操作浏览器的脚本（需填入按钮位置） |
| `parser.ts` | 把下载的数据转换成分析所需格式 |
| `autoAnalysis.ts` | 调用 AI 分析并保存结果到云端 |
| `index.ts` | 定时调度入口，每天两次自动运行 |
